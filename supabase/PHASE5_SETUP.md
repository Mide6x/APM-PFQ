## Content import

`content/questions/phase5-v1.json` contains 30 original bank questions (two per guide topic), separate from the 75 checkpoint questions. Difficulty is a practice label: Easy, Medium, Hard, Very hard. It is not an APM exam classification. All question IDs are stable (`PFQ-0001` etc). The first question uses Project environment completion; `PFQ-0002` also requires Business case completion to exercise the all-lessons rule.

Run `node scripts/import-questions.mjs` to validate every JSON batch in `content/questions/` and regenerate the SQL seed. Run with `--check` to confirm the committed seed matches. It rejects duplicate IDs/normalised stems, unknown topic/required-lesson/syllabus references, invalid difficulty/publication/version, duplicate or missing options, missing correct choices and empty explanations. Content authors must still review factual accuracy, ambiguous answers and near-duplicates. Never import production content through a browser or public API key; run the reviewed SQL in local/staging first and then through the project's authorised SQL editor/management connection.

## Access model

- `practice_questions` and `practice_question_lessons` hold only public metadata/prerequisite IDs, with published-only RLS and no browser writes.
- `apm_private.practice_question_content` contains stems, choices and answer keys. No browser role can read it directly, including after unlocking.
- `get_question_catalogue()` returns safe listing metadata and the current verified learner's status. Guests are Locked. Solved means at least one correct attempt on the current content version; a later retry does not erase it. Attempted means a current-set answer exists but none is correct.
- `get_practice_question()` returns only the question and four choices after checking publication and every required lesson. `submit_practice_question()` repeats these checks and grades against the private answer key. No checkpoint pass score is involved.
- Next.js independently checks verified sign-in and all required completion records before fetching a stem or submitting. Missing data/access fails closed. Personalised routes/actions are private/no-store.
- `question_attempts` has owner-only SELECT RLS and no browser writes. A fresh retry creates a new immutable attempt; repeated IDs return the original result, cannot cross ownership and do not bypass prerequisites. History uses ten rows per page, newest first.
- Account deletion cascades question attempts. No new app credential, cookie or analytics is required.
