# Phase 3 hosted setup

The catalogue is connected. Apply these new settings for magic-link sign-in and saved place; the public app key cannot change dashboard settings or run migrations.

1. Keep the **Confirm signup** and **Magic Link** email bodies link-based, using `{{ .ConfirmationURL }}` (Supabase defaults work). An optional branded body is in [`templates/magic-link.html`](templates/magic-link.html). Do not use the earlier code-only template. Keep email confirmation enabled, short single-use link expiry (10 minutes recommended), secure email change on both addresses, and provider send/verification rate limits. The app uses PKCE, so open each link in the same browser where it was requested. Request a separate link on another device to restore the same account.
2. Review and apply [`migrations/003_learner_progress.sql`](migrations/003_learner_progress.sql) to the existing hosted catalogue. It creates one private saved-place row per verified learner, with RLS ownership and no anonymous privileges. The migration is repeatable and has been tested locally with two learner identities.
3. Configure a production SMTP provider and verify delivery to addresses outside the Supabase organisation. The built-in email service is for development and restricts recipients/rate limits for magic links as well as codes; switching to links does not remove that restriction.
4. In Authentication → Security and protection, enable Cloudflare Turnstile using its secret key in the Supabase dashboard. Keep pre-clearance disabled. Add the real deployment domain and localhost to the widget's allowed hostnames. Put only the public site key in the app as `NEXT_PUBLIC_TURNSTILE_SITE_KEY`. Production sign-in requests fail closed if this key is missing. Local development without a site key is for testing only; never expose the dev server publicly.
5. Configure the Supabase Site URL and permitted redirect URLs for the deployed HTTPS origin. Allow `http://localhost:3000/auth/callback**` for local use (or `http://127.0.0.1:3000/auth/callback**` if that is the origin you open). Allow the deployed `https://YOUR-DOMAIN/auth/callback**` for production, scoped to that exact host/path; the suffix accommodates the validated `next` query. The app supplies `emailRedirectTo` and exchanges the returned code at `/auth/callback`. Keep request and callback on the same origin/browser. Do not share sign-in URLs. Redact callback query strings in hosting/proxy logs; Next.js dev request logging excludes this route. Finish hosting/region/log-retention and provider/privacy details from `PRIVACY_OPERATIONS.md` before public registration.
6. Verify two real accounts can each save a different place, read only their own record, reload, sign out locally and restore the same place in a second browser/device. Check expired, reused and wrong-browser links, resend limits, CAPTCHA rejection, email-change confirmation, and that sign-out removes this app's cookies. Verify personalised responses have `Cache-Control: private, no-store`.

No privileged Supabase key, database password or connection string belongs in the app environment or Git.
